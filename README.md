# ハコベル×タックスナップ インボイスキャンペーン（訴求アンケート）

ハコベルのドライバー向けに「インボイス登録＋タックスナップ利用で1年目の利用料をキャッシュバック」を案内し、
内容は 9/28 提案資料「ハコベルさま × タックスナップのキャンペーン設計」に準拠。
ニーズに合わせて ①申請フォーム ②登録手順の案内 ③割引クーポン ④お得診断 に振り分けるアンケート。
デザインと税額計算は `taxnap-survey-tedori`（手取りシミュレーション）を土台にしている。

- 公開URL: https://txto-inc.github.io/taxnap-campaign-hacobell/
- 導線: ①バナー（ハコベル）→ ②このアンケート → ③インボイス申請アンケート（Googleフォーム）

## ファイル

| ファイル | 用途 |
|---|---|
| `index.html` | 本体（単一HTML）。未確定の条件は冒頭の `CAMPAIGN`、連携先は `GAS_URL` などに集約 |
| `gas/Code.gs` | 回答の保存・メール自動送信（手順／クーポン／リマインド） |
| `tools/create_google_assets.py` | 回答スプレッドシートと申請フォームの作成スクリプト（作成済み） |
| `tools/shot.js` | 全経路を実ブラウザで通してスクショを撮る（`shots/` に出力） |

## 画面の流れ

```
ページ①趣旨（キャッシュバックのしくみ・申請の目安12/17・消費税の注意・青色の手取り表）
  └ ページ②選択肢
      ├ 1. キャッシュバックを受けたい → 登録状況
      │    ├ Ａ（ハコベルに番号登録済み）／Ｂ（未通知）→ 申請フォームへ（登録状況を事前入力）
      │    └ Ｃ（未登録）→ 氏名・メール・ドライバーID・同意 → 手順メール → リマインド
      ├ 2. 初年度割引だけ → 氏名・メール・ドライバーID・理由・同意 → 1人1コードのクーポンをメール（キャッシュバック対象外）
      └ 3. 診断 → 申告方法・売上・経費 → 手取り比較 → 1のＣ か 2 へ
```

## 診断の計算

- 2027年分どうしで「いまのまま／青色＋割引のみ／青色＋インボイス登録」を比べる
- 税額エンジンは手取りシミュレーション由来。**基礎控除だけ令和8・9年分の特例額に更新**（132万以下99万／489万以下104万／655万以下67万／超62万）。
  手取りシミュレーション側は改正前の値のままなので、流用するときは注意
- 検証値（9/28 提案資料 P12 と一致・経費率40%）: 300万 125.9/142.3/+16.4万、400万 171.4/189.5/+18.1万、500万 216.4/234.5/+18.1万
- 消費税は3割特例（課税標準×7.8%×30%＋地方分）。売上500万で 136,200円。納付額は経費に入れる
- アプリ利用料は1年目 21,780円（税込）。登録して条件を満たすと 19,800円がキャッシュバック
- 前提: 39歳以下・国民健康保険（東京23区）・単身
- ロジックを変えたら上の検証値で必ず確認する

## GAS セットアップ手順（初回のみ・約5分）

回答スプレッドシート「ハコベル_インボイスキャンペーン_回答」（Drive の「ハコベル_インボイスキャンペーン」フォルダ）で行う。

1. 拡張機能 > Apps Script を開き、`gas/Code.gs` の中身をそのまま貼って保存
2. プロジェクトの設定 > スクリプト プロパティ に登録

   | プロパティ | 値 |
   |---|---|
   | `POST_TOKEN` | `index.html` の `POST_TOKEN` と同じ文字列 |
   | `FORM_ID` | `10et5P25r3tYkgUIaISz471fjmLIOXldGKo_763M7m-8` |
   | `FORM_URL` | `https://docs.google.com/forms/d/e/1FAIpQLSfKvhI2WkcZrj74RWZ3FIm7m1STfaa9Mw0AEdBtTj2k4T2Tkw/viewform` |
   | `WEB_URL` | `https://app.taxnap.com`（省略可） |
   | `DEADLINE` | 締切日 `yyyy-MM-dd`（未定なら登録しない） |
   | `CONTACT` | 問い合わせ先（未定なら登録しない） |
   | `SENDER_NAME` / `FROM_ALIAS` / `REPLY_TO` | 差出人名／共有アドレス（Gmailの送信元に追加済みの別名）／返信先。任意 |

3. エディタで関数 `setup` を選んで実行（権限の承認が出るので許可）。シート作成と、毎朝9時のリマインド・フォーム送信時のクーポン送付のトリガーが登録される
4. デプロイ > 新しいデプロイ > 種類=ウェブアプリ、次のユーザーとして実行=自分、アクセスできるユーザー=全員
5. 発行された `/exec` URL を `index.html` の `GAS_URL` に貼って push

### 運用メモ

- **クーポン**: 「クーポン在庫」シートのA列に、Stripeで発行した1人1回用のプロモーションコードを並べておく。
  在庫が切れると「在庫切れ（未送付）」と記録され、補充後に `sendPendingCoupons` を実行すると未送付の人へ送る
- **差出人**: GAS を実行したアカウントのGmailから送られる。共有アドレスから送るなら `FROM_ALIAS` を設定
- **申請フォーム**: 送信時に「申請フォーム回答」シートへ写し、同じメールの未登録者のリマインドを止める。
  有料契約の確認・国税庁での番号確認・ハコベル連携日は同シートの列に手作業で記録する
- Code.gs を直したら「デプロイを管理 > ✏️ > 新バージョン」（「新しいデプロイ」は URL が変わる）
- 件数は `/exec` を GET すると JSON で見える（個人情報は返さない）

## 個人情報の扱い

- 回答スプレッドシートは個人情報を含む。共有はキャンペーン担当者に限定する
- ハコベルに提供するのは申請フォームで同意を得た項目（番号・氏名・ドライバーID・契約状況）のみ
- 「登録しない理由」は集計値だけを共有し、個人が分かる形では渡さない
